# Agentic AI Governance Policy

**Controls for Local LLMs, Coding Agents, Browser Automation & Approval Workflows**

> Version 1.0 | April 2026 | Confidential — Board & Senior Management

---

## 1. Executive Summary

The organisation is deploying AI agents — including local large language models (LLMs), automated coding assistants, and browser automation tools — to accelerate development and compliance workflows. These systems introduce material risks to data confidentiality, operational integrity, and regulatory compliance that require explicit governance controls aligned with our existing information security frameworks.

This policy establishes the minimum-acceptable controls for agentic AI systems, mapped to ISO 27001:2022 and ISO/IEC 38505-1:2022 (Governance of Data). It defines six control domains, 38 specific controls, a technical implementation checklist, and a RACI assignment table for enterprise rollout.

**Key risk areas addressed:**

- Data exfiltration via LLM inference endpoints and prompt logs (relevant to PDPO, AMLO, HKMA TRM)
- Supply-chain compromise of model weights and agent dependencies
- Prompt injection and adversarial misuse of deployed agents
- Unauthorized agent actions without human oversight or audit trail
- Model drift and bias in consequential decision support (AML, KYC scoring)

This policy applies to all agentic AI systems operated by or on behalf of the organisation, including third-party systems accessing organisational data or infrastructure.

## 4. Control Domains

The policy organises controls into six domains, each aligned to a specific category of agentic AI capability. Each domain carries a risk summary and the number of mandatory controls.

---

### Domain 1: Local LLM Deployment

**Risk Level: `CRITICAL`** | 6 controls

LLMs running locally (Ollama, vLLM) process internal data without the contractual safeguards of cloud providers. Key risks: model weight tampering, data exfiltration through inference APIs, uncontrolled resource consumption.

**Mandatory requirements:**

- Maintain a signed model inventory with use-case classification
- Network-isolate all inference workloads by default
- Validate model integrity via cryptographic checksums at startup
- Apply DLP controls to prevent regulated data submission to any internet-connected model
- Enforce rate limits and token quotas per service identity
- Maintain and enforce a model deprecation lifecycle

---

### Domain 2: Coding Agents

**Risk Level: `CRITICAL`** | 6 controls

Coding agents with access to source code, configuration files, and CI/CD pipelines can introduce vulnerabilities, exfiltrate secrets, or execute malicious dependencies if not properly constrained.

**Mandatory requirements:**

- Assign dedicated service accounts with minimal filesystem and API permissions
- Require SAST as a mandatory CI gate for all agent-generated code
- Block agent access to credential files; enforce pre-commit secret scanning
- Implement tool-call allowlisting to prevent arbitrary shell execution
- Use ephemeral session credentials with maximum time-to-live limits
- Scan all agent-suggested dependencies for CVEs and typosquatting

---

### Domain 3: Browser Automation

**Risk Level: `HIGH`** | 5 controls

Browser automation agents that interact with external systems, submit data, or execute financial transactions require strong containment and explicit human oversight for high-risk actions.

**Mandatory requirements:**

- Run all browser agents in ephemeral, network-isolated containers
- Enforce a domain allowlist with proxy-level enforcement
- Inject credentials from secrets manager at runtime; never hardcode
- Log all browser actions (URL, element, action type) to immutable storage
- Require human approval before any High or Critical risk browser action

---

### Domain 4: Prompt Logging

**Risk Level: `HIGH`** | 5 controls

Prompt and completion logs may contain sensitive personal data, commercially sensitive information, or AML case details. Their storage, access, and lifecycle must meet the same standards as production data.

**Mandatory requirements:**

- Publish and enforce a retention schedule aligned to AMLO and PDPO obligations
- Redact PII and case-sensitive data before log storage using automated pipeline
- Store logs in tamper-evident, append-only infrastructure with hash-chain integrity
- Apply RBAC — developers must not access production prompt logs
- Monitor log streams for jailbreak attempts, injection signatures, and exfiltration patterns

---

### Domain 5: Model Evaluation

**Risk Level: `HIGH`** | 5 controls

Models deployed in consequential workflows (AML scoring, KYC, credit) must be continuously evaluated for accuracy, safety, bias, and behavioral drift. Ad-hoc or undocumented evaluation is not acceptable.

**Mandatory requirements:**

- Define minimum-threshold evaluation scorecard before any model deployment
- Monitor production models for performance drift on a weekly automated cadence
- Conduct annual structured red-team exercises using OWASP LLM Top 10
- Complete bias and fairness audits annually for consequential AI models
- Version-control all evaluation datasets, benchmarks, and reports

---

### Domain 6: Approval Workflows

**Risk Level: `CRITICAL`** | 7 controls

Without explicit approval gates, agents can take consequential actions (writing to production, submitting external data, executing transactions) without human oversight. Approval workflows must be risk-calibrated, logged, and enforced at the infrastructure level.

**Mandatory requirements:**

- Publish an action risk taxonomy classifying all agent actions as Low / Medium / High / Critical
- Configure approval chains per risk tier (Low = auto, Critical = CISO + committee)
- Maintain immutable, 5-year approval audit logs for regulated workflows
- Enforce fail-closed behaviour on approval timeout — never auto-approve on expiry
- Enforce segregation of duties — initiators cannot self-approve
- Maintain and test rollback procedures for all High and Critical actions
- Define escalation triggers that notify CISO within 2 hours and board committee within 24 hours

## 7. Compliance, Exceptions & Review

### 7.1 Compliance Obligations

All controls in this policy are mandatory for in-scope systems. Non-compliance must be logged as a risk exception and accepted in writing by the CISO within 30 days of identification. Unaccepted exceptions escalate to the Risk Committee after 30 days.

### 7.2 Exception Process

- Submit exception request to CISO via risk register (include: control ID, system name, justification, proposed compensating control, target remediation date)
- CISO reviews within 10 business days
- Exceptions accepted for >6 months require Risk Committee sign-off
- All active exceptions must appear in the quarterly AI risk report to the board

### 7.3 Policy Review Schedule

| Review Type | Frequency | Owner |
|---|---|---|
| Full policy review | Annual (or after material AI deployment) | CISO |
| Control effectiveness testing | Quarterly | Security Architect |
| RACI roster review | Quarterly | Risk Manager |
| Red team exercise | Annual minimum | Security Architect + third party |

## 8. Key Definitions

| Term | Definition |
|---|---|
| **Agentic AI System** | An AI deployment that autonomously executes multi-step tasks, calls external tools, browses the web, or writes and runs code, with or without human intervention. |
| **Local LLM** | A large language model running on organisation-controlled infrastructure, not accessed via a third-party cloud API. |
| **Coding Agent** | An AI assistant integrated into an IDE or CI/CD pipeline that generates, modifies, or reviews source code autonomously. |
| **Prompt Injection** | An adversarial technique where malicious content in the agent's input overrides its instructions or causes unintended actions. |
| **Model Drift** | Degradation in model performance or behavioral consistency over time, caused by distributional shift in input data or environmental changes. |
| **Fail-Closed** | A control design principle where, in the absence of an explicit approval, the default action is denial — not authorization. |
| **AMLO** | Anti-Money Laundering and Counter-Terrorist Financing Ordinance (Cap. 615, Laws of Hong Kong). |
| **PDPO** | Personal Data (Privacy) Ordinance (Cap. 486, Laws of Hong Kong). |
| **HKMA TRM** | Hong Kong Monetary Authority Technology Risk Management Guidelines. |
